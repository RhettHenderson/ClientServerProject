## Project Overview
<p>This repository contains a **Client-Server application** built using C# with both **GUI** and **CLI** components. The application facilitates secure communication via **SSL/TLS** encryption. The **GUI** provides an intuitive interface for users, while the **CLI** offers the same functionality through command-line interactions. Both versions of the application rely on a shared backend to handle data transfer and encryption.</p>

<p>There are also pre-compiled binaries available in the `publish` folder for various platforms, allowing you to run the application without needing to build it yourself.</p>
<p>In general, you shouldn't run random binaries you find on the internet, but if you want them, they're there.</p>

## Instructions for Setting Up SSL Certificates

<p>Currently the application only runs with SSL, so it won't work without a certificate for the server. I'm considering adding the option to run without SSL in the future.</p>
<p>In order to run the application with SSL, you need to generate a development certificate, add it to Windows certificate manager, and configure the application to use it. Below are the steps to generate a **dotnet dev-cert**, add it to **certmgr** in Windows, and set up the thumbprint as an environment variable.</p>

### Step 1: Generate a .NET Development Certificate

<p>1. Open **Command Prompt** or **PowerShell** as Administrator.</p>
<p>2. Run the following command to generate a .NET development certificate:</p>
<pre>
dotnet dev-certs https --trust
</pre>
<p>3. This will generate and trust the development certificate on your local machine.</p>

### Step 2: Add the Certificate to Windows Certificate Manager

<p>1. Open the **Windows Certificate Manager** by pressing <code>Win + R</code>, typing <code>certmgr.msc</code>, and pressing <code>Enter</code>.</p>
<p>2. In **Certificate Manager**, navigate to the following path:</p>
<pre>
Personal > Certificates
</pre>
<p>3. You should see the **.NET Development Certificate** listed there. If it's not present, you may need to manually import it:</p>
<ul>
  <li>Right-click on the **Certificates** folder.</li>
  <li>Choose **All Tasks** > **Import**.</li>
  <li>Follow the wizard and import the certificate file generated by the <code>dotnet dev-certs</code> command.</li>
</ul>

### Step 3: Copy the Certificate Thumbprint

<p>1. In the **Personal** certificates store, find the certificate with the subject name `localhost` or similar.</p>
<p>2. Right-click on the certificate, select **Properties**, and then click on the **Details** tab.</p>
<p>3. Scroll down to find the **Thumbprint** field, and copy the thumbprint to your clipboard.</p>

### Step 4: Set the Thumbprint as an Environment Variable

<p>1. Open **Command Prompt** or **PowerShell** as Administrator.</p>
<p>2. Set the thumbprint in your environment variables by running the following command (replace <code>YOUR_THUMBPRINT</code> with the actual thumbprint you copied):</p>
<pre>
setx SERVER_CERT_THUMBPRINT "YOUR_THUMBPRINT"
</pre>

### Step 5: Verify the Setup

<p>1. After completing the above steps, the application should now be able to access the development certificate using the thumbprint stored in the environment variable.</p>
<p>2. You can test the application by running either the **GUI** or **CLI** version, ensuring that SSL is functioning correctly.</p>
